Tute & material delivery

Added 16 October 2026. Local preview uses fictional records. Backend unit checks do not replace a live database acceptance test.

1. Deploy the source and migrate

Back up the Frappe site and deploy this source using the existing installation guide. In the bench directory, run:

bench --site YOUR_SITE migrate
bench build --app institute_lms
bench restart

The migration creates IL Delivery Offer and IL Delivery Order. Deploy before opening delivery APIs; do not skip migration.

2. Assign the right package

Super Admin assigns Platinum to the class owner. Institute-owned classes use the institute account. Independent classes use the teacher account. Gold, Silver, Individual and unassigned accounts cannot enable or submit delivery orders. Overdue workspace restrictions still apply. Package changes follow the existing billing-cycle rules.

3. Teacher enables delivery

My classrooms → open a class → Tute delivery. Enable the option; enter the material title, description, total LKR price including delivery, and verified bank details. Institute-owned classes must use institute bank details. Save. Switching off stops new orders but keeps previous orders available while the plan remains eligible.

4. Student places an order

An enrolled student with active class access opens the same tab, enters recipient, international phone, residential address, city, postal code and country, and confirms the address. Transfer the exact displayed amount and submit a private PDF/PNG/JPEG slip up to 5 MB, transfer date and reference. Address details are private order snapshots, not public profile fields. Each material offer version permits one order per student; a rejected order can be resubmitted with a new slip.

5. Review and dispatch

The class teacher or institute admin views the slip, verifies actual bank receipt and records an approval or rejection note. Approval does not move money. Only approved orders can be marked dispatched, with courier and tracking reference. Students can see their order status. Changing material title, description, price or bank instructions creates a new offer version; previous orders keep their price and address.

6. Notifications and payments

New events: delivery.submitted, delivery.reviewed, delivery.dispatched. They use existing notification preferences and configured channels. Set up approved WhatsApp templates and email delivery before relying on external messages. Addresses and slips are not sent in notifications.

Online delivery checkout is intentionally unavailable: HNB merchant documentation and a verified delivery-order payment callback are not connected. Bank-slip review is implemented. Do not treat browser redirects as payment confirmation. No courier integration or automatic settlement is included. Delivery charges are separate from classroom fees and do not grant classroom access or add a billable classroom enrolment.

7. Acceptance checks before launch

  1. Use two students in different classes: neither should see the other’s addresses or slips.
  2. Try direct delivery API calls as a Gold account, unrelated teacher and suspended provider. All restricted actions must fail.
  3. Test enable/disable, required address confirmation, changed price, duplicate slip/reference, rejection and resubmission.
  4. Approve a real sandbox order only after verifying its payment; dispatch and verify student/institute notifications. Confirm new records survive server restart.
  5. Test on a narrow phone screen and with reduced motion enabled.

Local demonstration

Open the local preview on port 5182. Expand Preview scenarios, choose Platinum, choose Teacher, then open Edexcel O/L · Business → Tute delivery. A fictional LKR 750 offer and dispatched demo order were exercised in the current browser session. Switch to Gold to see the animated upgrade card. No money or messages are sent in preview.
